🛡️ HashiCorp Boundary — 접근제어는 어떻게 통제되는가

이 실습 환경(boundary dev)에서 실제로 돌아가는 접근제어 모델을 그림으로 설명합니다. Boundary 자체 Admin UI는 http://127.0.0.1:9200 에 있습니다 (admin / password).

1. 핵심 아이디어

사용자는 SSH 서버의 IP/포트를 전혀 알 필요가 없고, 직접 접속하지도 않습니다. 오직 Boundary 컨트롤러에 "이 target에 붙고 싶다"고 요청할 뿐입니다. 컨트롤러는 그 사용자가 권한(grant)을 가졌는지 검사한 뒤, 허용되면 워커를 통해 세션을 중개합니다.
→ 접근제어의 본질 = "누가(principal)" + "무엇에(target)" + "어떤 행동을(action)" 할 수 있는지를 role 안의 grant 로 정의하는 것.

2. 스코프 계층 (Scope Hierarchy)

모든 리소스는 스코프 안에 산다. 권한도 스코프 단위로 흐른다(상위→하위 상속 가능).

global scope · global
Auth Method ampw_1234567890 (password) User admin · alice · bob
계정/사용자가 여기 산다. dev 기본 role(아래)도 여기서 정의됨.
org scope · o_1234567890
조직 경계
project scope · p_1234567890
Target ttcp_… (tcp:2222 → SSH 컨테이너) Host Catalog → Host(127.0.0.1) → Host Set Role ssh-connect

3. 접속 요청이 허용/거부되는 흐름

STEP 1

인증 (authenticate)

alice/bob 이 password auth method 로 로그인 → 토큰 발급. 로그인 자체는 누구나 가능.

→
STEP 2

세션 인가 요청

authorize-session 을 target 에 대해 호출.

→
STEP 3 · 핵심

권한 검사

이 사용자의 role 들 중 이 target + authorize-session 을 허용하는 grant 가 있나?

→
STEP 4

허용 → 세션 중개

워커가 SSH 컨테이너로 연결을 프록시. 없으면 403 거부.

4. 권한 매트릭스 — 이번 실습의 실제 결과

사용자보유 Roletarget authorize-session grant결과
👩 alice ssh-connect (principal) ✔ 있음 (ids=target;actions=authorize-session) SUCCESS · 세션 인가됨
🧑 bob 없음 (기본 권한만) ✗ 없음 (dev 기본 grant 에서 authorize-session 회수함) DENIED · 403 Forbidden
💡 핵심: boundary dev 는 원래 인증된 모든 사용자에게 ids=*;type=target;actions=list,read,authorize-session 를 주는 'Authenticated User Grants' role 을 만든다. 그래서 그냥 두면 bob 도 접속된다. 실습 셋업 스크립트(2-setup.sh)에서 이 기본 grant 의 authorize-session 만 회수하여, 명시적 role 을 가진 alice 만 연결되게 만들었다.

5. 두 가지 UI / 통제 지점

① Boundary 내장 Admin UI

주소: http://127.0.0.1:9200

로그인: admin / password

OSS 바이너리에 포함된 웹 콘솔. 여기서 org/project, target, role, grant, 세션을 클릭으로 만들고 관리할 수 있다. boundary connect ssh 로 열린 세션도 실시간으로 보인다.

② CLI (이 실습이 쓰는 방식)

boundary targets create, roles add-grants, roles add-principals, targets authorize-session …

UI 가 하는 모든 일을 스크립트로 자동화한 것. 접근제어 규칙이 코드로 남아 재현 가능.

6. 직접 해보기

  • ./scripts/3-test-access.sh alice → 성공, … bob → 거부
  • bob 에게 권한 주기: boundary roles add-principals -id=<ssh-connect role> -principal=<bob user> 후 다시 테스트 → bob 도 성공으로 바뀐다.
  • 실제 SSH 접속: ./scripts/4-ssh.sh (비밀번호 devpass)
  • 내장 UI 에서 같은 리소스를 눈으로 확인: :9200

이 페이지는 정적 설명용이며, 실제 통제는 위 두 UI/CLI 를 통해 Boundary 컨트롤러가 수행합니다.
