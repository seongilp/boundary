1. 구조 한눈에

사용자(alice/carol/bob) │ ① Boundary 로그인 (신원) ▼ ┌─────────────┐ ② authorize-session (권한검사) │ Boundary │──────────────┐ │ dev (9200) │ │ ③ 세션 중개 (proxy) └─────┬───────┘ ▼ │ ④ Vault 동적자격증명 요청 ┌──────────────┐ ▼ │ ssh-target │ :2222 ┌─────────────┐ │ (devuser) │ │ Vault (8200)│ ├──────────────┤ │ 동적 DB계정 │───────────────────▶│ pg-target │ :5432 └─────────────┘ 임시계정 생성 │ (appuser/동적)│ └──────────────┘
  • Boundary — 누가 어떤 리소스에 접근 가능한지 통제(role/grant). 직접 접속 차단, 프록시 경유.
  • Vault — 접속 시마다 임시 DB 계정 발급 → TTL 만료 시 자동 폐기 (zero-standing-privilege).
  • Terraform — 접근제어 규칙을 코드로 선언 (GitOps 단일 소스).

# 3) 접근제어 매트릭스 확인
./scripts/matrix.sh

# 4) 실제 접속
./scripts/connect-ssh.sh               # alice 로 SSH
./scripts/connect-pg.sh carol dynamic  # carol 로 DB (Vault 동적 자격증명)
./scripts/connect-pg.sh carol static   # carol 로 DB (고정 자격증명 brokering)

# 5) 정리
./scripts/down.sh                      # (--destroy 추가 시 terraform destroy)

5. 핵심 개념

5.1 신원은 2층이다

층계정관리 주체
① Boundary 신원alice, carol, bobBoundary (role/grant)
② 타겟 안 계정devuser, appuser, v-token-…서버/DB (또는 Vault)

alice 로 Boundary 에 로그인해도 SSH 서버엔 devuser 로 들어간다. 둘은 별개.

5.2 접근제어 3요소

role = 누가(principal) + 무엇에(target) + 어떤 행동(grant: authorize-session)

5.3 Credential 관리 3단계

방식동작이 프로젝트
직접 입력사용자가 비번 타이핑(기본)
BrokeringBoundary 가 저장한 비번을 건네줌pg-target (정적)
Vault 동적접속마다 임시계정 발급·자동폐기pg-dyn-target

6. 새 리소스 추가 (GitOps 방식)

CLI 로 만들지 말고 terraform/ 에 선언 후 ./scripts/apply.sh.

# terraform/targets.tf
resource "boundary_target" "redis" {
  name         = "redis-target"
  type         = "tcp"
  scope_id     = var.project_scope_id
  default_port = 6379
  address      = "127.0.0.1"
}

# terraform/roles.tf  (alice 에게 권한)
resource "boundary_role" "redis_connect" {
  name            = "redis-connect"
  scope_id        = var.project_scope_id
  grant_scope_ids = ["this"]
  grant_strings   = ["ids=${boundary_target.redis.id};actions=authorize-session,read"]
  principal_ids   = [boundary_user.this["alice"].id]
}

8. FAQ

접속할 때마다 스크립트를 돌려야 하나?
아니다. 로그인은 가끔(boundary authenticate), 접속은 boundary connect ssh -target-id=… 만 반복. 토큰은 keyring 에 저장돼 재사용.

alice/bob 은 로컬 사용자인가?
그렇다. Boundary password auth method 의 로컬 계정. 실무에선 OIDC/LDAP(SSO)로 대체.

postgres.boundary.dev 같은 건?
boundary dev 가 깔아둔 예제 alias(더미). 무시.

접근제어 개념 다이어그램은 web/index.html 참고.
